## Story

As **Ash (GPC admin)**,
I want **to open `/admin/directory` and decide every pending listing from its card — publish in one click, hold or reject in two — without losing my scroll position, search or which cards I've expanded**,
so that **clearing the queue is fast on a laptop or a phone, and nothing I've already looked at makes me look at it twice**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given `/admin/directory` loads, when the page renders, then it shows a tablist (Pending/Held/Published/Rejected/Unpublished) with live counts, oldest-first cards carrying business name, category, description, links, public contact, and a private-details disclosure — plus a legend explaining each status — with the pending count also visible on the admin shell (sidebar pill, dashboard quick-link card, and the browser `<title>`).
2. Given a pending card, when the admin clicks **Publish**, then only that card shows a busy state, the write completes via 5.2a's action endpoint, and on success the card settles in place with an outcome line, attribution, a notification-status placeholder, and a 10-second **Undo** — it does not disappear from the list.
3. Given a pending card, when the admin picks **Hold** or **Reject**, then the Decision Dialog (built on 5.1's `Dialog`) opens with the matching reason chips from `5.2a`'s reason maps; each chip commits the action immediately except **"Something else"**, which reveals a required textarea before a real confirm button.
4. Given a listing has been waiting 5-9 / ≥10 working days, when the queue renders, then it carries a warning/overdue rail-plus-chip and sorts above younger rows within its tab, and the ≥10-day case is also reflected in the sidebar's pending-count text.
5. Given a decision resolves (from a card, or on return navigation from 5.3's review screen), when the list re-renders, then scroll position, active tab, search term, sort order, and any expanded private-details disclosures are all unchanged, and a decided row stays visible in place until "Clear N decided", a tab/search/sort change, or a reload.
6. Given more than 25 rows exist in the active tab, when the admin clicks **"Show 25 more"**, then the fetched range widens and the new rows append without resetting scroll, search, or previously-revealed rows.

- Card wireframe, exact structure and copy — status pill + waiting chip, business name (`<h2>`), category · submitted date, clamped description with "Show all N characters", link icons row, public contact, "▸ Member details (private)" disclosure, then Publish (primary, 44px) / Hold+Reject (equal weight, 44px) / Review & edit (full width) — desktop reorders to Review & edit · Reject · Hold · Publish, destructive furthest from the dominant action. [Source: EXPERIENCE.md#screen-m-s1--moderation-queue]
- Status vocabulary and Badge variants (Pending/Published/Held/Rejected/Unpublished) come from 5.1's `Badge.jsx` — do not re-implement the pill; a pill is never the only carrier, every row also restates status in words. [Source: EXPERIENCE.md#3-moderating-the-directory] "Status vocabulary" bullet; component: 5.1.
- Waiting thresholds and treatment: `WAITING_WARN_DAYS = 5` (4px `--color-warning` rail + "⏱ Waiting 6 days" chip, sorted above younger rows), `WAITING_LATE_DAYS = 10` (`--color-error` rail, "⏱ Waiting 12 days — overdue", pinned to top, counted in the sidebar badge); the rail duplicates the chip so colour is never the sole signal; default sort is oldest-first for the same reason. [Source: EXPERIENCE.md#3-moderating-the-directory] "Waiting too long" bullet.
- Place-preservation, verbatim rules (this codebase already shipped and fixed this exact bug once, commit `310e86c`): **P1** `loading` set only when nothing is on screen yet, post-decision refetch is silent, list never unmounts, row count read via a ref not a dependency; **P2** a decided row settles in place at its previous index/height, leaves only on "Clear N decided" / tab-filter change / reload; **P3** `visible` and the expanded-disclosures `Set` reset only on tab/search/sort change; **P4** full queue state (tab, search, sort, `visible`, expanded ids, scroll) survives a round trip to 5.3's review screen, and on return the reviewed row scrolls into view and gets focus. [Source: EXPERIENCE.md#3-moderating-the-directory] "Keeping her place" bullet.
- Bounded fetch: `PAGE_SIZE = 25`, ranged query, "Show 25 more" widens and appends; tab counts from a separate exact-count query so a badge never costs a page of rows. [Source: architecture.md#component-moderation-admin]; [Source: EXPERIENCE.md#3-moderating-the-directory] "Bounded fetch" bullet.
- Reversibility: Publish⇄Unpublish and Hold/Reject⇄"Move back to pending" are all permanent-until-reversed, so the 10-second **Undo (n)** is a convenience, not a time limit on an essential function (WCAG 2.2.1); the countdown is text, never an animated ring. [Source: EXPERIENCE.md#3-moderating-the-directory] "Reversibility" bullet.
- Signup-email-as-public-contact warning: inline text on the contact line ("⚠ This is the same as her signup email. Publishing it puts her personal address on the public site."), never blocks Publish, links to Reject → `contact_unsafe`. [Source: EXPERIENCE.md#journey-m1--ash-clears-the-pending-queue] table row.
- Decision Dialog reuse: this is **the** `Dialog` primitive (5.1), not a second one; beyond §2.9's props it takes `choices` (each chip IS a confirm button, footer renders Cancel only), `busy`, and a `children` slot for the private note + email checkbox + preview toggle. [Source: DESIGN.md#29-modal--dialog-new-extends-confirmmodal]; wireframe and exact reason vocabularies at [Source: EXPERIENCE.md#screen-m-s3--decision-dialog].
- Pending count everywhere: sidebar `Directory` pill at `ml-auto`, accessible name "Directory, 3 pending" (overdue: "…, 1 waiting more than 5 working days"); Dashboard card replaces its chevron with the count; `<title>Directory (3) | GPC Admin`; fetched with the shell, not lazily; zero renders as **no pill**, never "0". ## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. NEVER run tests or quote coverage here. -->

- **Approach:** manual/functional verification per AC plus an accessibility keyboard/screen-reader pass on the tablist and cards; no automated test runner exists in this repo. [Inference]
- **Key scenarios:** publish from a card with no reason required; hold with a canned reason; reject via "Something else" (must not commit without a note); overdue sort ordering at the 5/9/10/12-day boundaries; deciding one of three visible rows and confirming the other two keep their identity/position/expanded state after the silent refetch; "Show 25 more" appending without resetting scroll/search; returning from 5.3's review screen to the same scrolled, focused row.
- **Per-AC verification:** AC#1 → seed 3+ pending listings, confirm oldest-first ordering and count parity across the tab, sidebar, dashboard and `<title>`; AC#2 → publish, assert only the acting card is `busy`, then assert the settled-row copy/attribution/Undo render; AC#3 → open the dialog for Hold and Reject, exercise every reason chip plus "Something else" with an empty textarea (must not commit); AC#4 → seed listings at 4/6/11 days old, assert rail colour/chip text/sort position/badge text at each boundary; AC#5 → decide one row, scroll, expand a disclosure on another, trigger the refetch, assert nothing else moved; AC#6 → seed 30 pending rows, assert the first 25 render and "Show 25 more" appends the remaining 5 without disturbing scroll.
- **Fixtures/mocks:** seeded `directory_listings` rows across all five statuses with varying `submitted_at`/age; a mock authenticated session; a listing whose `enquiry_email` equals the member's signup email (for the warning path); a listing with `publish_listing` consent withdrawn (for the disabled-Publish state).
- **Edge cases:** zero pending rows (explanatory empty state, not blank/error); the fetch itself rejecting (banner + Try again, list not refetched); a decision write failing (in-card `role="alert"`, nothing else on the page moves); the last row in a tab being decided (queue-clear panel appears **below** the settled rows without stealing focus from the last Undo); Publish disabled when publish-consent is absent (dimmed but focusable, reason reachable via `aria-describedby`); a 401 mid-session ("You've been signed out… nothing you decided has been lost" + re-auth returning to the same tab).

## Learnings from Previous Stories

- From 5.1: `Dialog`, `Spinner`, and the moderation `Badge` variants are ready to consume as-is — do not re-implement any of the three. The responsive `AdminLayout` drawer and skip link are already in place.
