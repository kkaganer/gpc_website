## Story

As **Ash (GPC admin)**,
I want **to see whether a member was actually emailed about my decision, and to retry, copy the message, or mark it sent by hand when the automatic send didn't work**,
so that **a broken email integration never leaves a member wondering what happened, and the record always stays honest about what actually happened**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given a listing's `outbound_emails` row, when its status is `disabled` / `queued` / `sent` / `failed` / `given_up` / `not_applicable`, then 5.2b's queue row and 5.3's review screen each render the matching state via one shared `EmailStatusChip`, always as a node **separate** from the listing's own status pill — never merged into one ambiguous "Error".
2. Given a `failed` or `given_up` row, when the admin clicks **"Try again"**, then it calls the retry endpoint (which re-invokes 5.5a's `attemptSend()`), and on success the chip updates to `sent` with a timestamp **without** altering the listing's own `status`.
3. Given a `failed`/`given_up` row, when the admin clicks **"Copy the message"**, then the exact rendered subject + body (via 5.5a's `emailTemplates.js`) is copied to the clipboard, and a pre-filled `mailto:` link is also offered.
4. Given a `given_up` row, when the admin clicks **"Mark as sent by hand"**, then the row's status reflects that it was sent manually and an attributed history entry is written — the record never claims the system sent something it did not.
5. Given a `not_applicable` row (hold, or an admin who chose not to email), when the admin clicks **"Email her after all"**, then the send preview re-opens and, on confirm, the row is queued and sent exactly as the original decision would have triggered.

- NFR-011 governs this whole story: "the decision and the send are two operations. A failed send never rolls back a decision, and the pill and the notification chip are always separate nodes with separate roles." [Source: EXPERIENCE.md#notification-states-fr-021-fr-022]
- Six-state copy table, verbatim:
  - `disabled` → *"No email sent — email sending is off for now. [ Copy the message to send yourself ]"* (plain text; also offers a pre-filled `mailto:`).
  - `queued`/`retrying` → *"Emailing Hannah now…"* / *"Trying again…"* + `Spinner`, in the polite live region.
  - `sent` → *"✉ Emailed hello@littleacorns.co.uk at 14:07, 18 Aug 2026."*
  - `failed` → `role="alert"`: *"We couldn't email her — **your decision was saved**. Last tried Mon 18 Aug, 21:14. «reason»"* + **Try again** + **Copy the message**.
  - `given_up` → *"Still not sending after three tries. Copy the message and email her yourself — her address is hello@littleacorns.co.uk."* + **Copy the message** + **Mark as sent by hand**, which writes an attributed history entry so the record stays honest.
  - `not_applicable` → *"No email sent — you chose not to."* + **Email her after all**, which re-opens the preview.
  [Source: EXPERIENCE.md#notification-states-fr-021-fr-022]
- FR-021: "Given sending fails, when the admin views the listing, then the failure is visible and can be retried; the moderation decision itself is not rolled back." [Source: prd.md#FR-021]
- NFR-013: "100% of publish, reject, unpublish, edit **and erasure** actions record the acting admin and a UTC timestamp" — "Mark as sent by hand" is itself an attributable action and must follow the same rule, even though it is not one of the four moderation-status transitions. [Source: prd.md#NFR-013]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. NEVER run tests or quote coverage here. -->

- **Approach:** manual/functional verification per AC; no automated test runner exists in this repo. [Inference]
- **Key scenarios:** retry a `failed` row that then succeeds; retry a `failed` row that fails again; retry a `given_up` row; copy-to-clipboard content equality against the rendered template; "Mark as sent by hand" producing a history entry with actor + timestamp; "Email her after all" reopening the preview and, on confirm, queuing + attempting a send.
- **Per-AC verification:** AC#1 → render each of the six states in isolation with static props and diff against the copy table; also render the chip next to the listing's status `Badge` and assert they are separate DOM nodes with separate `role`s; AC#2 → stub a successful retry, assert `status: 'sent'`, `sent_at` set, and the listing's own `status` column unchanged in the same read; AC#3 → click "Copy the message", read the clipboard (or the copy handler's argument in a test harness), assert exact string equality with `emailTemplates.js`'s rendered output; AC#4 → mark a `given_up` row as sent by hand, assert an `actioned_by`/`actioned_at` history entry is written and the chip no longer offers "Mark as sent by hand" again; AC#5 → trigger "Email her after all" on a `not_applicable` row, confirm the preview shows the correct template, and confirm queues + attempts a send.
- **Fixtures/mocks:** `outbound_emails` rows in each of the six states; a mock authenticated session; a stubbed `attemptSend()` (from 5.5a) returning both success and failure outcomes for the retry checks.
- **Edge cases:** retrying a row that another admin has already retried in the interim (should not double-send — confirm the retry endpoint is safe to call concurrently, or document the accepted risk); "Mark as sent by hand" on an already-`sent` row (should be a no-op / not offered, since the button only appears at `given_up`); clipboard API unavailable (older browser / permissions) — confirm the `mailto:` fallback still works.
