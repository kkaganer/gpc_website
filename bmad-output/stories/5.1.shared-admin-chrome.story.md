# 5.1: Shared admin chrome — responsive layout, dialog, spinner, motion reset, moderation badges

**Story ID:** 5.1
**Epic:** 5 — Moderation and shared admin
**Slug:** shared-admin-chrome
**Status:** ready-for-dev

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **Ash (GPC admin)**,
I want **a responsive admin shell with one dialog primitive, one shared spinner, a global reduced-motion reset, and a moderation status-pill vocabulary**,
so that **every admin screen built in Epics 5, 7 and 8 gets consistent, accessible chrome instead of each one re-inventing modals, loading states and status colours**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given the viewport is below 768px, when any authenticated admin route renders inside `AdminLayout`, then the sidebar collapses to an off-canvas drawer behind a `☰` trigger inside a sticky top bar carrying the page title and a slot for the pending-count pill; at ≥768px the existing permanent `w-64` rail renders unchanged.
2. Given `AdminLayout` has no `Layout.jsx` wrapper and therefore no skip link today, when any admin page loads, then a skip-to-content link is present (visually hidden until focused, `--color-primary-700` on focus for contrast) and moves focus to `<main id="admin-main-content">` on activation.
3. Given a new `Dialog` primitive, when it opens, then it satisfies `role="dialog"` + `aria-modal="true"` + `aria-labelledby`, moves focus into it, traps Tab, closes on Escape and returns focus to the invoking element, marks background content inert, and is not dismissible by the backdrop alone; `ConfirmModal` is rebuilt on top of it, preserving `{ title, message, onConfirm, onCancel }` for its existing call sites and adding `confirmLabel`, `confirmTone` (`primary | destructive`), `requireReason`.
4. Given the copy-pasted `animate-spin` markup used across the codebase, when it is extracted into one shared `Spinner` component, then in-flight buttons and page-load skeletons consume it, and under `prefers-reduced-motion: reduce` it renders a static (non-rotating) indicator while a live region carries the loading state in words.
5. Given `prefers-reduced-motion: reduce`, when any animation anywhere on the site fires (not only new admin routes), then it is removed rather than sped up — via a `useMotionSafe()` hook wrapping framer-motion's `useReducedMotion()` and a global `@media (prefers-reduced-motion: reduce)` block in `src/index.css` zeroing animation/transition duration and `scroll-behavior` on `*`.
6. Given `Badge.jsx` today only exposes `free | sold-out | new | upcoming | past`, when five moderation variants (`pending | published | held | rejected | unpublished`) are added, then each renders the `DESIGN.md` §2.7 verified text/background colour pairs with an `aria-hidden` icon **and** visible text (never colour alone), and the existing five variants are unchanged.

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. NEVER run tests or quote coverage here. -->

- **Approach:** manual/functional verification against each AC plus a code-review pass for the accessibility contract (no automated test runner exists in this repo). [Inference]
- **Key scenarios:** resize across the 768px breakpoint and confirm the drawer/rail swap with no layout shift of content; open the drawer, confirm focus trap and that Escape (or route change) closes it; tab to the skip link on first keystroke and confirm it jumps focus correctly; open `Dialog` via the rebuilt `ConfirmModal` from each of its existing call sites and confirm none of their behaviour regressed; toggle OS-level reduced-motion and confirm the `Spinner` stops rotating, page transitions/hovers stop animating, and nothing that previously conveyed state-via-motion now conveys nothing; render all five new `Badge` variants next to the five existing ones and check contrast + icon-plus-text presence.
- **Per-AC verification:** AC#1 → resize test at 767px/768px; AC#2 → keyboard-only pass, Tab-from-top lands on the skip link first; AC#3 → programmatic focus/Tab-cycle/Escape check on `Dialog`, plus a diff of each existing `ConfirmModal` call site's rendered output before/after; AC#4 → toggle `prefers-reduced-motion` in devtools and observe the `Spinner`; AC#5 → toggle the same OS setting and grep the rendered DOM/computed styles for zero-duration transitions on a known animated element (e.g. the existing `Button` hover); AC#6 → render each `Badge` variant and check text/background against the specified hex pairs.
- **Fixtures/mocks:** none required — this story has no server or data dependency; every check is renderable in isolation with static props.
- **Edge cases:** a `Dialog` opened with a destructive first control (focus should land on the heading, not the destructive button); a `Dialog` opened while another is already open (should not be possible — note if the codebase currently allows nested modals); the skip link's target existing on every admin page once other stories add routes; `Spinner` used both standalone (page skeletons) and inside a `<button>` (in-flight actions) rendering correctly in both contexts.
