# 3.2: Join page shell, intro, identity section and navbar CTA

**Story ID:** 3.2
**Epic:** 3 — The public form
**Slug:** join-page-shell
**Status:** ready-for-dev

## Story

As a **prospective member arriving at `/join` from any entry point**,
I want **a branded, single-scrolling-page form that loads GPC's own configuration, tells me
honestly how long it will take, collects my four unconditional details, and clearly says when
sign-ups are paused**,
so that **I can start joining without being sent to a third-party tool, and I know before I type
anything whether this is worth my time right now**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Given a visitor opens `/join` while the form is open, when the page loads, then it renders one
   `<h1>` (GPC's own branded title, not a third-party embed), the admin-authored intro text as
   plain text, a length signal reading `"About «M» minutes · «N» questions"`, and section 1's four
   unconditional fields — first name, email, postcode, how-heard — each with a
   programmatically-associated `<label htmlFor>`.
2. Given the published form config fails to load, when `GET /api/join/config` errors or the
   request rejects, then the page shows an explicit retry state (**never** silently falling back
   to the closed state or the open form) with a `Try again` action.
3. Given the form is closed (`is_open = false`), when a visitor opens `/join`, then no `<form>`
   element and no field is rendered anywhere in the DOM — not hidden, not disabled — and instead
   an admin-authored closed message and three alternative links (What's On, Directory, newsletter)
   are shown.
4. Given the visitor is on any public page, when they view the navbar, then a `Button`-styled
   `Join` call-to-action appears to the right of the nav row (not as a seventh text `NavItem`) and
   links to `/join`.
5. Given the postcode field, when the visitor types a value that does not match a UK postcode
   shape, then a debounced (600ms) inline message appears without blocking submission at this
   point, and clears once the value looks valid.
6. Given the visitor's viewport is 320px wide, when the page renders, then there is no horizontal
   scroll and every field remains operable by keyboard alone.

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from the planning docs WITH SOURCE CITATIONS. -->

- **FR-001 is this story's core contract:** "a publicly reachable, GPC-branded form at a stable
  path (`/join`)... renders every unconditional question from the source form inventory in the
  documented order," fully keyboard-operable, no question answerable only by pointer, operable at
  360px. [Source: prd.md#FR-001]
- **One scrolling page, not a stepped flow (D1).** No navigation event between sections; numbered,
  named, counted sections (`«k» of «T» · Section name`), each gaining a `Done` badge when its
  required fields are answered. This story owns section 1 ("1 of «T» · About you") and the shell
  around it; later stories mount sections 2+. [Source: EXPERIENCE.md#1-joining--the-public-form —
  "D1", "D2"]
- **The length signal is computed, never authored (D3/A12).** `«N»` = questions **currently
  rendered for this member's branch**; `«T»` = sections currently rendered. Recomputed on every
  branch change (3.3's job) but this story renders it correctly for the unconditional-only state
  before any branch is chosen. Announced through the shared live region **only on change**, never
  on first paint. [Source: EXPERIENCE.md#1-joining--the-public-form — "D3"]
  [Source: ux-drafts/ADJUDICATIONS.md#a12-question-count]
- **Screen S1 field spec, verbatim helper copy:**
  - First name — `autocomplete="given-name"`, required.
  - Email — helper "We'll only use this to contact you about GPC.", `autocomplete="email"`,
    required.
  - Postcode — helper "We use this to plan events near you. It's never shown publicly and never
    leaves GPC.", `autocomplete="postal-code"`, required, **debounced 600ms**, three-state border
    feedback matching `EventFilters.jsx`'s idiom, **no geocoding** (a geocoder is a third-party
    processor that would have to be added to the privacy disclosures, for a field that must stay
    private). Error copy: *"That doesn't look like a UK postcode. Try something like SE10 8XJ."*
  - How did you hear about us — `RadioGroup`, options: Greenwich Parents & Carers, Weekly
    newsletter, Instagram, A friend, At an event, Google, Something else — required. **The typo
    fix:** the source form's option reads "Weekly Newletter"; this story's rendered copy must read
    "Weekly newsletter". [Source: EXPERIENCE.md#1-joining--the-public-form — Screen S1 wireframe
    and states table]
- **Field content (labels/help/options) comes from the published form config** (`GET
  /api/join/config`, built in Epic 2 story 2.2), **not from a hard-coded string in this story's
  components** — the field *set*, *type* and *branch membership* are code-defined in
  `src/lib/join/questions.js` (owned by Epic 2 story 2.1; this story reads it, never edits it),
  while label/help/required/options are the admin-editable DB overlay. Render generically off
  `type`, don't hard-code seven distinct field components.
  [Source: architecture.md#adr-008-form-configuration-code-defined-registry-database-overlay-and-versioned-publish]
  [Source: context/sharding-context.md#owned-filemodule-scope]
- **Config-fetch failure must never be mistaken for a decision.** *"We couldn't load the form just
  now."* / *"This is our end, not yours."* + `Try again`; after two failures the copy adds
  `gpc.communitynews@gmail.com`. **Never** fall back to the closed state (a failed fetch is not an
  admin decision) and never fall back to "open" (submissions would be rejected downstream by
  FR-009). [Source: EXPERIENCE.md#1-joining--the-public-form — Journey J1 states table, Screen S1
  Error state]
- **Screen S4 (closed) is content-complete, never a raw null.** If the admin left the message
  blank: `<h2>` stays, body becomes *"We've closed the form for now. We'll open it again soon —
  sign up to the newsletter below and we'll let you know."* Three alternatives row: What's On,
  Directory, weekly newsletter (reuse the existing `NewsletterBanner` inline) — each a 48px full
  row where the accessible name is the whole sentence, not a bare "→". No `<form>` element exists
  anywhere on this screen. A 409 mid-session must replace the page with this same screen plus a
  leading, focused, `tabindex="-1"` alert: *"Sorry — sign-ups closed while you were filling this in.
  Nothing was saved."* — that mid-session variant is 3.8's job (submit-time handling); this story
  only needs to build S4 as a mountable component 3.8 can render.
  [Source: EXPERIENCE.md#1-joining--the-public-form — Screen S4] [Source: prd.md#FR-009]
- **Navbar CTA, not a seventh NavItem (A11).** `/join` enters the navbar as a `Button`-styled CTA
  to the right of the nav row — seven text links wrap at 1024px. This is `src/components/layout/
  Navbar.jsx`, listed contended in the collision map and **owned by this story**; nobody else may
  edit it for this purpose (6.1 separately owns adding the `/directory` NavItem to the array).
  [Source: ux-drafts/ADJUDICATIONS.md#a11-join-enters-the-navbar-as-a-cta-button-not-a-seventh-text-link]
  [Source: context/sharding-context.md#owned-filemodule-scope]
- **Skip link:** one already exists at `src/components/layout/Layout.jsx:8-10`, wrapping every
  public page including `/join`. **Do not add a second one.** Its contrast fix
  (`--color-primary` → `--color-primary-700`) and `focus:`→`focus-visible:` fix belong to Epic 6
  per the cross-cutting ownership table, not this story.
  [Source: EXPERIENCE.md#dev-handoff-notes — "Cross-cutting work that belongs to no single
  section"]
- **Reading width caps at `max-w-2xl` (672px) regardless of viewport** for `/join` — a wide form
  is harder to complete, not easier. [Source: DESIGN.md#1.4-breakpoints]
- **One `<h1>` per page** — `SectionHeading` always renders `<h2>` and cannot be the page title;
  this story needs the new page-heading pattern (30px/700 Poppins mobile → 40px desktop,
  `--color-dark`). [Source: DESIGN.md#2.11-page-heading]
- **NFR-009's weight budget applies to this route as a whole**: `/join` must be `lazy()`-loaded so
  its weight never lands on visitors who never join, and its initial render must add no more than
  50KB gzipped over the existing site shell — a constraint every later Epic 3 story inherits, not
  just this one. [Source: prd.md#NFR-009] [Source: EXPERIENCE.md#1-joining--the-public-form —
  "NFR-009, second clause"]
- **Loading state:** `<h1>` paints immediately (it's static); skeletons at the heights of the
  first three sections below it — skeletons for page load, per the shared `Spinner`/skeleton
  convention (3.1a's `Banner`/spinner primitives + the site-wide skeleton idiom), not a spinner
  for a whole-page load. [Source: EXPERIENCE.md#1-joining--the-public-form — Screen S1 states
  table] [Source: DESIGN.md#2.12-loading-skeleton]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify per AC, test types, fixtures, edge cases. -->

- **Approach:** component/integration tests against a mocked `GET /api/join/config` (success,
  error, `is_open: false`), plus a manual 320px keyboard-only pass and a manual screen-reader
  pass on S1 and S4.
- **Key scenarios:** open-state render shows the four identity fields with correct labels; a
  config fetch rejection shows the retry state and never the closed state; `is_open: false`
  renders zero form fields in the DOM; the navbar CTA is present and links to `/join` on every
  public page; postcode debounce fires at 600ms, not on every keystroke.
- **Per-AC verification:** AC #1 → assert `<h1>` count is 1, assert each of the 4 fields has a
  `label[for]` matching an `input[id]`; AC #2 → mock a rejected fetch and assert the retry banner
  renders, not S1's fields or S4; AC #3 → mock `is_open: false` and assert
  `document.querySelectorAll('form, input, select, textarea').length === 0`; AC #4 → render
  `Navbar` and assert the CTA is a `<Link>`/`<a>` to `/join` outside the mapped `NavItem` list; AC
  #5 → type an invalid postcode, advance fake timers 600ms, assert the message appears; type a
  valid one, assert it clears; AC #6 → resize the test viewport (or a manual pass) to 320px and
  assert no element's computed width exceeds the viewport.
- **Fixtures / mocks:** a mock `GET /api/join/config` response shaped like Epic 2's contract
  (`is_open`, `intro_text`, `closed_message`, resolved question config for `always`-branch
  fields); this story does not implement that endpoint (Epic 2, story 2.2) and must stub it.
- **Edge cases to cover:** admin closed-message is an empty string (fallback copy renders, not a
  blank card); config fetch succeeds but returns zero `always`-branch questions (should not
  happen given the registry, but the component must not crash); rapid successive postcode edits
  within the debounce window (only the last value is validated).
