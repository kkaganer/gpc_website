# 2.6: Admin form preview

**Story ID:** 2.6
**Epic:** 2 — Form configuration
**Slug:** admin-form-preview
**Status:** ready-for-dev

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **Ash, a GPC admin**,
I want **to see exactly what a member would see in each branch, including my unpublished
edits, without it creating a member record or touching any counter**,
so that **I can check my wording before I publish it, the same way I'd proof-read anything
else before sending it.**

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Given an admin opens `/admin/join-form/preview`, when they change the "Viewing as" control
   between Not chosen yet / Business Mums / Career Mums / Both, then the frame re-renders the
   real public form component in that branch, sourced from the current **draft**
   (label/help/required/option edits included, whether or not they have ever been published).
2. Given the admin submits the previewed form after it passes the form's real client-side
   validation, when the submit completes, then it returns **without issuing any network
   request** — no `POST /api/join/submit` call, so no member row, listing, consent record,
   rate-limit counter, honeypot counter, or server log line is created or moved by a preview
   submission.
3. Given the "Form state" control is set to Closed inside the preview chrome, when the frame
   re-renders, then it shows the closed-form state using the current draft's closed message —
   and this **never** changes the real, live `form_settings.is_open` value; the chrome's
   controls affect only what is rendered inside the frame.
4. Given the preview route sets `isPreview` on the rendered form, then that flag is derived
   **only from the route itself**, never from any request body, query string, or client-set
   value that a forged request could replicate — a preview render can never be coerced into
   the real submission path.
5. Given the draft fails to load, then the chrome renders with a banner — "Couldn't load the
   preview. Your draft is safe — go back to settings and try again." — and `[Back to
   settings]` / `[Try again]`; the admin's draft itself is never at risk from a failed preview
   load.
6. Given the preview's own accessibility contract, then tab order visits every chrome control
   before any control inside the previewed form, and the previewed form's own heading levels
   are demoted by exactly one level relative to how they render on the real `/join`, so the
   admin page's outline stays valid.

**FR-010, verbatim acceptance criteria.** "Given an admin previews the form, when they select
each group option, then they can inspect the Business, Career and Both branches. Given a
preview is submitted, when it completes, then no member record, listing, or consent record is
created. The preview reflects unsaved draft edits, so wording can be checked before
publishing." [Source: prd.md#FR-010]. This story's three ACs above map directly onto those
three sentences.

**"The previewed form is the real `JoinForm` component, not a mock: if preview and production
can diverge, preview is worthless."** [Source: EXPERIENCE.md#4-configuring-the-form — Screen
S3, "Preview safety contract"]. This is the single most important design constraint on this
story, and it creates a genuine cross-epic sequencing conflict that this story cannot resolve
on its own: `JoinForm` is Epic 3's deliverable, and `epics.md`'s dependency map states Epic 2
**blocks** Epic 3 (via 2.1/2.2), not the reverse
[Source: epics.md#epic-2-form-configuration — "Blocks: **Epic 3**"]. If this story is
implemented in Epic-2 order, there is no real `JoinForm` to mount yet. **Recommendation to the
orchestrator, not a decision this story makes unilaterally:** schedule the actual
component-mounting task (and this story's full acceptance) after Epic 3's rendering stories
(3.3–3.7) land, even though the story keeps its Epic-2 number and slug for planning
continuity. Everything else in this story (the chrome, the `isPreview` contract, the
network-free submit contract, the accessibility rules) can be built and reviewed against a
placeholder form component in the interim. [Inference — sequencing judgment, not sourced]

**Preview safety contract, verbatim.** "`isPreview` is set by the route, never by a
user-supplied value, so it cannot be forged into a real submission path. On submit the
preview runs the form's **real client-side validation**... then returns **without issuing any
network request**: no endpoint, so no rate-limit, honeypot or rejection counter moves and no
server log line appears. The chrome's `Form state` affects only the render and never the real
open/closed state." [Source: EXPERIENCE.md#4-configuring-the-form — Screen S3, "Preview
safety contract"]. Concretely: `isPreview` should be derived from the route match itself
(e.g. a boolean the route's element sets as a literal prop), never read from `location.state`,
a query param, or anything a crafted URL could set to `true` against the *real* `/join` route.
[Inference — mechanism]

**Chrome controls, verbatim wireframe elements.** Viewing as (`Not chosen yet` / `Business
Mums` / `Career Mums ✓` / `Both`), Directory opt-in toggle, Form state (`Open` / `Closed`
select), Width (`Phone` / `Full` select); the framed region carries a "Draft preview · N
unpublished changes" banner and is a named `role="region"` labelled "Preview of the public
join form" [Source: EXPERIENCE.md#4-configuring-the-form — Screen S3 wireframe and
accessibility notes]. ≥1024px: side-by-side becomes the default, question list left, preview
right [Source: EXPERIENCE.md#4-configuring-the-form — Screen S3, "≥1024px"] — this is a nice
to have for this story's sizing; the single-column/stacked layout satisfies every AC on its
own and the side-by-side mode can be deferred if it threatens the one-dev-day sizing.
[Inference]

**Tab order and heading demotion, verbatim.** "Tab order never enters the previewed form
before the chrome controls... The previewed form's headings are **demoted one level**, the
single deliberate divergence from production rendering, required to keep the admin page's
outline valid." [Source: EXPERIENCE.md#4-configuring-the-form — Screen S3 accessibility
notes]. Heading demotion should be a prop the real `JoinForm` component accepts (e.g. a
`headingLevelOffset` or similar) — this story specifies the *requirement*; the actual prop
shape is Epic 3's to design since it owns the component being demoted. [Inference]

**Never disabled.** "The preview's own submit is **never** disabled — disabling it would
prevent Ash checking the validation behaviour she came to check."
[Source: EXPERIENCE.md#4-configuring-the-form — Screen S3 states table, "Disabled"].

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. NEVER run tests or quote coverage here. -->

- **Approach:** manual verification, chrome-and-contract-only until Epic 3's `JoinForm`
  exists, then a full integration pass once it is mounted; no automated test runner exists in
  this repo (see 2.1's Testing note).
- **Key scenarios:** switch "Viewing as" through all four values and confirm the correct
  branch renders (or, pre-Epic-3, that the placeholder receives the correct branch prop);
  submit the preview form and confirm — via network inspection — that literally zero requests
  fire to `/api/join/submit` or any admin abuse-summary endpoint; edit a draft label in
  another tab (2.4), reload the preview, and confirm the new wording appears without any
  publish having happened; set Form state to Closed while the real form is Open and confirm
  the `StatePreviewWarning` banner appears and the real `form_settings.is_open` value is
  unchanged after the session.
- **Per-AC verification:** AC #1 → branch-render correctness per "Viewing as" value. AC #2 →
  network-request assertion (dev-tools network tab, zero preview-triggered requests) plus a
  direct check that no new row appears in `members`/`member_submissions`/`abuse_events` after
  a preview submit. AC #3 → `form_settings.is_open` before/after comparison. AC #4 → attempt
  to set `isPreview` via a crafted query string against the real `/join` route and confirm it
  has no effect there (this assertion technically exercises Epic 3's route, included here
  because it is this story's safety contract). AC #5 → simulate a draft-fetch failure and
  confirm the banner and both recovery actions. AC #6 → tab-order and heading-level manual
  check with a screen reader or the accessibility tree inspector.
- **Fixtures/mocks:** a draft with at least one unpublished label change and one unpublished
  option retirement, so "reflects unsaved draft edits" is actually exercised rather than
  trivially true against a clean draft.
- **Edge cases:** previewing with `Viewing as: Not chosen yet` — the group question renders
  with nothing selected and no branch section, matching the "Empty" state described in
  `EXPERIENCE.md`'s S3 states table (dashed placeholder inside the frame, visibly chrome, not
  an error) [Source: EXPERIENCE.md#4-configuring-the-form].
