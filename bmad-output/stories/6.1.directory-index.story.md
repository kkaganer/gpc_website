# 6.1: Public directory index

**Story ID:** 6.1
**Epic:** 6 — The public business directory
**Slug:** directory-index
**Status:** ready-for-dev

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **public visitor (local parent) with no account**,
I want **to browse every published member business at `/directory`, and narrow the list by category or a search term**,
so that **I can find a relevant local business quickly, and reach the same filtered view again by reloading or sharing the URL**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Given at least one published listing exists, when a visitor opens `/directory`, then every published listing renders as a card showing business name, category and description only — no member name, signup email, or postcode appears anywhere on the page.
2. Given zero published listings exist (the launch condition), when `/directory` loads, then Empty State A renders with the specified copy; search and category controls remain visible but disabled (never hidden), and a `[List your business]` link to `/join` plus a link to `/whats-on` are present.
3. Given a visitor types a search term or selects a category, when results update, then only listings matching all whitespace-split search tokens against business name, description or category, and the selected category, are shown — with no page reload — and the page's one polite live region announces the new result count.
4. Given an applied filter combination matches no listing, when results render, then Empty State B renders, naming the active search term and/or category, and offers a "Clear filters" action.
5. Given filters are applied via search or category, when the visitor reloads the page or opens a shared URL, then the same filtered view is restored from `?q=` and `?category=` query parameters; clearing all filters removes those parameters from the URL (`/directory`, not `/directory?q=&category=all`).
6. Given the listings fetch is in flight or fails, then a skeleton-card loading state or a retryable error state renders respectively — never a blank page and never stale data shown alongside an error.
7. "Directory" is reachable as an item in the site's main navigation (desktop row and mobile drawer) at every screen width, linking to `/directory`.

**Architecture and data access**
- This page reads `directory_listings` directly from the browser with the anon key — **no API route**. That is safe *only* because `directory_listings` is structurally incapable of holding personal data (no column capable of it exists) and only `published` rows are RLS-visible to `anon`; this pattern must never be copied onto any other table [Source: architecture.md#adr-001-split-public-and-private-data-across-separate-tables-and-revoke-column-access-on-the-public-one] [Source: architecture.md#component-directory-public — "No API route; there is nothing private to protect and no reason to add a hop"].
- Column grant to `anon` is exactly: `id, slug, business_name, category_id, description, website_url, instagram_url, enquiry_email, published_at`. `status`, `member_id`, `reject_reason`, `submitted_*` and `actioned_*` are **not** granted — do not attempt to select or filter on them client-side; the RLS policy `for select using (status = 'published')` already does the gating [Source: architecture.md#5-data-model — Entity: directory_listings].
- `directory_categories` (`id`, `key`, `label`, `sort_order`, `retired_at`) is publicly readable "the directory filter needs it" [Source: architecture.md#5-data-model — Entity: directory_categories]. Filter by `key`, never by `label` or `id`, so a category rename under FR-017 never breaks a shared filtered URL [Source: EXPERIENCE.md#6-the-public-directory — "Filtering is by category identifier, not display name"] [Inference: `key` is the stable identifier, not `id`, because it is the human-legible, URL-friendly form and both are equally rename-proof].
- **Bound: fetch capped at 500 published listings**, `order by published_at desc` [Source: architecture.md#adr-007-client-state-hand-rolled-hooks-fetch-once-filter-client-side]. This is a *fetch* cap, not a *render* cap — the render slice is 24 with "Show N more" (see below).
- Hook name and shape follow ADR-006's own example: `useDirectoryListings.js` in `src/hooks/`, returning `{ data, loading, error }` (here `{ listings, categories, loading, error }`) [Source: architecture.md#adr-006-naming-conventions].
- **No new runtime dependency.** No React Query/SWR, no search library, no fuzzy matching, no stemming — substring matching only [Source: architecture.md#adr-007-client-state-hand-rolled-hooks-fetch-once-filter-client-side] [Source: EXPERIENCE.md#6-the-public-directory — "no fuzzy-matching library is introduced (NFR-012)"]. `react-hot-toast` exists in `package.json` for other features but must **not** be used here — no global toaster; use inline banners/live regions only [Source: sharding-context.md — UX rulings, A6].

**FRs satisfied**
- FR-018 (public directory index — every published listing shown, card fields limited to business name/category/description/link-presence, empty state, loading state, reachable from nav) [Source: prd.md#FR-018].
- FR-019 (category filter, text search matching name/description/category, no-results state with a way to clear, URL-restorable filtered view, keyboard-operable controls that announce result counts) [Source: prd.md#FR-019].
- NFR-001 (zero private fields retrievable by the anon key) is the reason the column grant above is exhaustive — this story must not add a select on any ungranted column [Source: prd.md#NFR-001].
- NFR-009 (directory interactive ≤3s on 4G at 100 listings) drives "no images anywhere" and "one request, one round trip" — `InitialTile` (a CSS-only decorative tile, no image) supplies per-card identity at zero network cost [Source: EXPERIENCE.md#6-the-public-directory — Performance section] [Source: prd.md#NFR-009].
- NFR-010 (usable at 300 published listings, no unbounded fetch) is satisfied by the 500-row `.limit()`, not by hope [Source: prd.md#NFR-010].

**The addendum-Q1 constraint — no location, anywhere**
- This release publishes **no location of any kind** — not a postcode, not an outcode, not an area name; this is an explicit, standing product decision, not an oversight [Source: addendum.md#Q1] [Source: prd.md — Out of Scope, "Publishing any location, even approximate"].
- Design works *inside* the constraint: the `<h1>` reads "Member businesses", never "local businesses" for an individual listing (two words also overflow the 320px nav row) [Source: EXPERIENCE.md#6-the-public-directory — Navigation]; the intro states the absence out loud once, verbatim: *"We don't publish business locations — if you need someone nearby, ask when you get in touch."* [Source: EXPERIENCE.md#6-the-public-directory — Screen S1 wireframe]. Do not invent a location field, an area string in the description, or a distance filter — category plus text search are the entire discovery mechanism [Source: EXPERIENCE.md#6-the-public-directory — "The honesty note"].

**UX/UI acceptance detail**
- Exact Empty State A copy (verbatim, do not paraphrase): heading "**The directory is just getting started**"; body "There aren't any businesses listed yet. This is where you'll find photographers, childminders, coaches, bakers and therapists — all run by Greenwich Parents & Carers members." then "If that's you, you can be the first. Listing is free and takes about five minutes."; actions `[ List your business ]` → `/join` and "See what's on locally instead" → `/whats-on` [Source: EXPERIENCE.md#6-the-public-directory — Screen S1, Empty state A].
- Empty State B: typed term echoed as **plain text, truncated at 60 characters**, never re-parsed or linkified; an unknown `?category=` value is **never** echoed and is dropped from the URL via `replace` while results render unfiltered with a dismissible note [Source: EXPERIENCE.md#6-the-public-directory — Screen S1, Empty state B and decision-points table].
- Card grid: `grid-cols-1` → `md:grid-cols-2 gap-8` → `lg:grid-cols-3`; a 4th column is explicitly rejected [Source: EXPERIENCE.md#6-the-public-directory — Screen S1, Responsive]. Reference existing grid idiom at `src/pages/Events.jsx` (`grid grid-cols-1 md:grid-cols-2 gap-8`) [Inference: adapted from constraints-brief "Card grid" reference].
- Card component extends `src/components/ui/Card.jsx` (no internal padding — wrap in `p-6`) [Source: DESIGN.md#2-6-card-extend]. **The card is not a click target** — the business name is the only real `<a>`; a stretched-link pseudo-element may extend its hit area, but the anchor stays the accessible name and tab stop. Do **not** copy `LondonEventCard`'s `<div onClick>` pattern — it is keyboard-unreachable [Source: DESIGN.md#2-6-card-extend] [Source: EXPERIENCE.md#6-the-public-directory — Drop-off notes].
- `LinkPresenceRow` renders **indicators, not live links** — a live `mailto:` on the index would make every member's enquiry address scrapeable from one page. Icons are `aria-hidden`, each paired with visually-hidden text ("Has a website" / "On Instagram" / "Accepts enquiries") [Source: EXPERIENCE.md#6-the-public-directory — Screen S1, Components].
- New Badge `category` variant: 14px/600, `--radius-full`, 4px 12px padding, filled `--color-primary-700` (`#c9107f`, 5.43:1 on white) — **do not** reuse the `upcoming` variant or copy `SubscribersManager`'s pill colours, which fail AA [Source: DESIGN.md#2-7-status-pill-extend] [Source: sharding-context.md — UX rulings, A15].
- Render slice starts at 24 and resets to 24 on any filter change (the `SubscribersManager` idiom: `PAGE_SIZE`, "Show N more", reset-on-filter-change) [Source: EXPERIENCE.md#6-the-public-directory — Search and filter contract]. Reference implementation: `src/pages/admin/SubscribersManager.jsx` (`PAGE_SIZE = 100` pattern; here the constant is 24, matching EXPERIENCE.md's "first 24 render; Show 23 more").
- Search input: `type="search"`, `enterKeyHint="search"`, autoComplete/autoCorrect/autoCapitalize off, `spellCheck={false}`, native `-webkit-search-cancel-button` suppressed in favour of one 44×44 clear button; Enter blurs rather than submits; Escape clears and keeps focus [Source: EXPERIENCE.md#6-the-public-directory — Accessibility].
- Filter region is a `<search>` landmark (or `<section role="search">`); `ResultsStatus` is the page's single `aria-live="polite"` region, mounted empty on first render (a region inserted with its content already present is not reliably announced), `aria-atomic="true"`, pluralised correctly, debounced 400ms after the last keystroke, immediate on a category change [Source: EXPERIENCE.md#6-the-public-directory — Accessibility]. This is the page's one A13 region [Source: sharding-context.md — UX rulings, A13].
- Focus moves only after "Show more" (to the first newly revealed card heading) and after "Clear filters"/clearing search (to the search input) — never on a keystroke or count change [Source: EXPERIENCE.md#6-the-public-directory — Accessibility].
- Input/select styling tokens: 48px height, `--color-border #6b7280` (4.83:1) border, `--radius-xl`, 16px font (mandatory, prevents iOS zoom) [Source: DESIGN.md#2-4-text-input-textarea-select-new-pattern]. Reference the existing `selectClass`/dimmed-disabled idiom in `src/components/whatson/EventFilters.jsx:48,184-193`, but do **not** copy its 600ms-debounced network call — filtering here must stay entirely client-side/in-memory [Source: EXPERIENCE.md#6-the-public-directory — Drop-off notes, citing `EventFilters.jsx`'s postcode debounce as the anti-pattern].
- Skip link: `src/components/layout/Layout.jsx:8-10` already exists and wraps this page — do not add a second one. It currently fails AA (`focus:` not `focus-visible:`, and paints on `--color-primary` `#fc16a0` at 3.64:1); because the directory index is one of NFR-008's three named pages, recolouring it to `--color-primary-700` is in scope for this work [Source: EXPERIENCE.md#6-the-public-directory — "Shell correction, stated once"] [Source: DESIGN.md#2-13-navigation]. **This edit touches a file no story explicitly owns in the collision map — flagged below.**

**Accessibility floor (applies here in full)** — every input has `id` + `<label htmlFor>`; the filter region is a genuine landmark; errors are not applicable here (no form submission) but disabled states carry `aria-describedby` explaining why; 16px minimum on inputs; visible `:focus-visible`; touch targets ≥44×44px; no horizontal scroll at 320px; `<button>`/`<a>` only, never `<div onClick>` [Source: sharding-context.md — Accessibility floor (NFR-008)].

## Testing

- **Approach:** No test runner is configured in this repo — `package.json` has no `test` script and no `vitest`/`jest`/`@testing-library` dependency [Inference, from direct inspection]. Verification is manual/inspection-based against a seeded Supabase environment, run once per AC as a documented checklist rather than an automated suite, unless the dev tool separately logs a decision to add a test runner (a new dependency, per NFR-012).
- **Key scenarios:** (a) 0 published listings — Empty State A, controls disabled-not-hidden; (b) 1–3 published listings — `JoinInvitationCard` appended as the final grid cell; (c) ~50 published listings across ≥3 categories, including one category with 0 published listings and one retired-but-referenced category — normal filtering; (d) a search term matching 0 rows; (e) `?category=` naming a value that doesn't exist; (f) throttled/offline network — loading skeleton then a retryable error; (g) keyboard-only pass: Tab through search → select → Clear filters → each card → Show more.
- **Per-AC verification:** AC #1 → inspect rendered DOM for absence of any personal-data field across all seeded volumes; AC #2 → seed 0 listings, confirm exact copy and disabled-not-hidden controls; AC #3 → type a token, select a category, confirm live-region announcement text and debounce timing; AC #4 → seed a filter combination with 0 matches, confirm Empty State B copy and "Clear filters"; AC #5 → apply filters, reload the URL directly, confirm restored state, then clear and confirm the URL has no query string; AC #6 → simulate a rejected/slow fetch (devtools network throttling or a temporarily revoked anon grant in a non-prod project) and confirm skeleton then error, never stale content; AC #7 → resize to 320px/768px/1440px and confirm the nav item and mobile-drawer entry at each.
- **Fixtures / mocks:** seed `directory_listings` at three volumes (0, 1–3, ~50) with mixed `website_url`/`instagram_url` presence and at least one category with a `retired_at` set but still referenced by a published row; no images are needed anywhere (FR-D02 deferred).
- **Edge cases to cover:** rapid typing (only one live-region announcement per idle 400ms window, not one per keystroke); a business name/description at the 300-character description cap; a category select showing "(0)" for an active-but-empty category; `prefers-reduced-motion` on the skeleton (no pulse) and on any card entrance animation.
